# Станция проверки кодов маркировки (MVP)

Монолитное приложение для участка упаковки: кладовщик загружает расходный ордер из 1С,
сканирует коды маркировки (DataMatrix) через сканер на COM-порту, приложение проверяет
код в «Честном ЗНАКе», сверяет товар и количество с ордером и формирует отчёт в CSV.

Стек: C# / .NET 8 (ASP.NET Core Minimal API + SignalR), SQLite, HTML/JS + Bootstrap.
Результат сборки — **один исполняемый файл** `MarkCheck.exe` (вёрстка и библиотеки встроены внутрь).

## Сборка

```cmd
dotnet publish -c Release -r win-x64 -o publish
```

Получится `publish\MarkCheck.exe` (~50 МБ, .NET на машине не нужен).
Рядом с exe при первом запуске создаётся каталог `data\` с базой `markcheck.db`.

## Запуск

1. Запустить `MarkCheck.exe` (окно консоли оставить открытым).
2. Открыть в браузере `http://localhost:5080`.
3. Раздел «Администрирование»: выбрать COM-порт сканера и его скорость, вставить
   токен True API «Честного ЗНАКа», указать ИНН организации. Сохранить.
4. Раздел «Проверка»: загрузить `.xlsx` расходного ордера → сканировать товар.

Адрес/порт меняется в «Администрировании» (`http_url`), например `http://0.0.0.0:8080`
для доступа с других ПК в сети. Изменение применяется после перезапуска.

## Логика проверки кода

1. Сканер отдаёт строку в COM-порт → фоновая служба `ScannerService` собирает её до CR/LF
   и передаёт в обработчик; результат мгновенно уходит в браузер через SignalR.
2. Разбор GS1 DataMatrix: извлекаются GTIN (AI 01) и серийный номер (AI 21),
   формируется КИ `01<GTIN>21<Serial>` для запроса в ЧЗ. Криптохвост (91/92/93) отбрасывается.
3. Контроль дублей: код уже в текущем ордере → «дубликат»; код был в другом ордере → «уже отгружен».
4. Сопоставление GTIN → номенклатура (`Products`). Если GTIN неизвестен, оператору
   показывается окно выбора товара из открытого ордера, связка сохраняется в базу.
5. Проверка в «Честном ЗНАКе» (`POST /api/v4/true-api/codes/check`): валидность кода,
   статус (`INTRODUCED`/`APPLIED`), ввод в оборот, возможность реализации, совпадение
   `ownerInn` с ИНН организации. Адрес CDN-площадки определяется автоматически (см. ниже).
6. Контроль количества по строке ордера: при превышении плана код помечается ошибкой.
7. Любая ошибка → красный экран, звуковой сигнал, требование отложить товар;
   запись сохраняется с признаком `SetAside`, чтобы попала в отчёт.
8. «Завершить проверку» — ордер закрывается, оба отчёта (простой CSV с кодами и подробный)
   генерируются и сохраняются в базе, открывается окно с кодами маркировки для копирования в 1С.

Товары без признака маркировки (`[М]` в ордере / галочка в справочнике) проверяются
только по количеству; для них допускается сканирование обычного EAN-13.

## Восстановление после сбоя

Ордер и все сканирования пишутся в SQLite сразу. После перезагрузки браузера или ПК
активный ордер и уже проверенные коды подтягиваются автоматически (`GET /api/state`).

## Структура проекта

```
MarkCheck.csproj              сборка в один файл, встраивание wwwroot в exe
Program.cs                    хост, DI, все HTTP-эндпоинты, выгрузка CSV
Data/Models.cs                модели Product / Order / OrderLine / ScannedItem / OrderReport / ScanResult
Data/Db.cs                    SQLite: схема, соединения, таблица настроек
Hubs/ScanHub.cs               канал SignalR (сервер → браузер)
Services/ScannerService.cs    чтение COM-порта, автопереподключение
Services/Gs1Parser.cs         разбор GS1 DataMatrix (GTIN, серийный номер, КИ)
Services/TrueApiClient.cs     клиент True API «Честного ЗНАКа»
Services/OrderParser.cs       разбор печатной формы расходного ордера 1С (.xlsx)
Services/ScanProcessor.cs     бизнес-логика проверки кода (включая fallback-поиск по GTIN)
Services/NomenclatureImportParser.cs  разбор файла импорта номенклатуры 1С (.xlsx)
wwwroot/index.html, work.js   рабочее место упаковщика
wwwroot/nomenclature.html     справочник номенклатуры (код 1С, наименование, GTIN)
wwwroot/journal.html          журнал ордеров и статистика
wwwroot/admin.html            настройки (COM-порт, токен ЧЗ, ИНН, адрес сервера)
```

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/state` | активный ордер, строки, сканирования, состояние сканера |
| POST | `/api/orders/upload` | загрузка .xlsx ордера (`force=1` — закрыть предыдущий) |
| POST | `/api/orders/{id}/close` | закрыть ордер |
| GET | `/api/orders/{id}/codes` | коды успешных сканирований (JSON, для окна копирования) |
| GET | `/api/orders/{id}/csv` | CSV с кодами маркировки (только коды, для вставки в 1С), хранится в базе |
| GET | `/api/orders/{id}/csv-full` | подробный отчёт в CSV (сводка расхождений + все коды со статусами), кнопка «Детали» в журнале |
| POST | `/api/scan` | проверка кода (ручной ввод) |
| POST | `/api/map` | сопоставить GTIN со строкой ордера и перепроверить код |
| POST | `/api/scans/{id}/setaside`, DELETE `/api/scans/{id}` | отложить / удалить запись |
| GET/POST/DELETE | `/api/products…` | справочник номенклатуры, `POST /api/products/import` — импорт из `.xlsx` |
| GET | `/api/journal`, `/api/journal/{id}` | журнал и детали ордера |
| GET/POST | `/api/settings` | настройки; `POST /api/cz/test` — проверка связи с ЧЗ |
| POST | `/api/admin/clear-journal` | очистить журнал сканирования и все ордера (с автобэкапом БД) |
| POST | `/api/admin/clear-nomenclature` | очистить справочник номенклатуры (с автобэкапом БД) |

## Разбор ордера из 1С

Парсер ищет строку заголовков, содержащую «Код», «Товар» и «Количество», и распределяет
значения строк по диапазонам колонок — поэтому объединённые ячейки и сдвиг колонок
печатной формы не ломают разбор. Берётся колонка «Количество» в базовых единицах
(не «Количество (упаковок)»). Признак `[М]` в строке трактуется как «подлежит маркировке».

Проверено на файле `Расходный ордер № ИБ-36263`: распознаны номер, получатель, склад
и 7 строк товара с количествами и признаком маркировки.

## Импорт номенклатуры из 1С

Страница «Номенклатура» → «Импорт» принимает файл `.xlsx` в формате выгрузки 1С со столбцами
«Штрихкод», «Номенклатура.Код» (или «Код»), «Номенклатура.Наименование» (или «Наименование»)
и «Характеристика.Наименование» (или «Характеристика»). Наименование товара формируется как
`Наименование (Характеристика)` — например, «Джинсы (серые XL)»; если характеристика не указана,
берётся только наименование. GTIN извлекается из штрихкода: поддерживаются GS1-строки вида
`(01)04603764218092(10)HH2117960701`, коды с хвостом `**`, а также обычные 8–14-значные штрихкоды.
При повторном импорте существующие записи (по GTIN) обновляются, а не дублируются.

## Поиск товара по GTIN (устойчивость к ведущим нулям)

При сканировании GTIN из кода маркировки (14 знаков) ищется точное совпадение со значением
в справочнике `Products`; если не найдено — дополнительно проверяются вариант без ведущих нулей
и вариант, дополненный нулями слева до 14 знаков. Это устраняет несовпадения, когда GTIN в 1С
или в файле импорта был выгружен без ведущего нуля (например, `4600000000017` вместо
`04600000000017`).

## Ограничения MVP и что делать дальше

- **Токен ЧЗ вводится вручную.** Используется токен для ККТ (разрешительный режим) — он выдаётся один на ИНН
  в личном кабинете ЧЗ (markirovka.crpt.ru → Профиль → «Токен для контрольно-кассовой техники»)
  и передаётся в запросе через заголовок `X-API-KEY`. Старый хост `markirovka.crpt.ru` для этого метода
  больше не работает (HTTP 410). Полноценный True API (для отправки документов оборота, а не просто
  проверки кодов) требует 10-часового JWT-токена с подписью ГОСТ УКЭП
  (`auth/key` + `auth/simpleSignIn`) — в MVP не реализован, т.к. для станции достаточно проверки
  перед продажей.
- **Автообнаружение CDN-площадки.** `https://cdn.crpt.ru` — только точка входа для обнаружения
  (прямой запрос на `codes/check` даёт HTTP 404). При базовом URL `https://cdn.crpt.ru` приложение само
  вызывает `GET /api/v4/true-api/cdn/info`, получает список активных площадок (`cdn01`, `cdn04`...),
  при нескольких — выбирает самую быструю по `cdn/health/check`, и кеширует выбор на 2 часа
  (настройка `cz_resolved_host`). При HTTP 404 от выбранной площадки кеш сбрасывается и обнаружение
  повторяется один раз. Если в настройках указана конкретная площадка (например, `https://cdn01.crpt.ru`) —
  автообнаружение не запускается, запрос идёт напрямую на указанный адрес.
- **Отчёты хранятся в базе** (таблица `OrderReports`) один раз при закрытии ордера, поэтому кнопки
  скачивания в журнале работают повторно (без HTTP 404), даже после перезапуска приложения.
- **Два вида CSV**: простой (только коды маркировки, для вставки в 1С оператором) и подробный
  (сводка расхождений + все коды со статусами, доступен через кнопку «Детали» в журнале). После
  завершения сканирования открывается окно с кодами — можно скопировать в буфер без скачивания файла.
- **Офлайн-тестовый режим ЧЗ** (настройка «Администрирование» → «Офлайн-тест»): позволяет проверять
  работу станции без реального токена и связи с ЧЗ — ответ имитируется случайно (~85% успех,
  15% отказ с разными причинами). Не использовать в продуктивной работе — только для демонстраций/обучения.
- **Нет работы с агрегатами (SSCC/короба)** — сканируются только потребительские КМ.
  При необходимости добавляется запрос состава короба в ЧЗ и автозачёт вложений.
- **Нет возврата результата в 1С.** Логичный шаг: выгрузка кодов в 1С (файл/HTTP-сервис)
  для заполнения документа отгрузки и последующего вывода из оборота.
- **Нет авторизации пользователей** — станция считается доверенной. При необходимости
  добавляется вход по PIN и фиксация оператора в журнале.
- Рекомендуется доработать в 1С кнопку выгрузки строгого CSV/JSON вместо печатной формы —
  это уберёт риск поломки парсера при изменении печатной формы.
- Полезные развития: печать этикетки/акта проверки, контроль сроков годности из ордера,
  дашборд производительности по операторам.

## Опасная зона (администрирование)

На странице «Администрирование» есть раздел «Опасная зона» с двумя отдельными кнопками:
«Очистить журнал сканирования и ордера» (удаляет `Orders`, `OrderLines`, `ScannedItems`,
`OrderReports`, справочник номенклатуры не затрагивается) и «Очистить справочник номенклатуры»
(удаляет `Products`, журнал и ордера не затрагиваются). Перед любым удалением обе кнопки автоматически
создают полную копию файла базы данных в папке `data\` с именем вида
`delete-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.db` — на случай ошибочной очистки. Для подтверждения действия нужно
ввести слово **УДАЛИТЬ** — кнопка удаления недоступна, пока слово не введено точно.
